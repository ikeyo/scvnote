# 2026-09-09 ScvNote 인수인계서

## 세운 계획

처음 계획은 "프로젝트 멤버끼리 비밀번호 공유"였다. 진행 중 두 번 방향이 바뀌었다.

1. 비밀번호 공유 (RSA-OAEP 봉투 암호화) — **폐기**. 평문 HTTP에서 `crypto.subtle`을 쓸 수
   없어 우회 계층이 계속 늘어났고, 개발용 자격증명 보관에 그 복잡도가 맞지 않는다고 판단해
   서버 측 암호화로 갈아엎었다
2. 노트 본문을 마크다운 원문으로 저장 — MCP 왕복을 무손실로
3. 빌드 번호 표시 · 화면 폭 · 첨부 · 본문 대목에 할 일 달기
4. 작업일지에 빌드 줄 요구 (저장소가 연결된 프로젝트만)

## 해야 할 것

**1. 나스 업데이트** — 다른 모든 확인이 여기에 걸려 있다.

```bash
cd /volume1/docker/scvnote && git pull && sudo ./scripts/setup-nas.sh
```

끝나면 로고 옆이 **`#17`** 로 바뀐다. 안 바뀌면 재빌드가 안 된 것이다.
(`sudo` 없이 실행하면 도커 소켓 권한으로 막히고, 이제 그 자리에서 해결법을 안내한다)

**2. 화면 확인 — 이번 작업에서 눈으로 보지 못한 것들.** 코드 검증만 된 상태다.

## 막힌 것

- **화면 확인을 하지 못했다.** 세션 중반에 브라우저 도구 사용을 중단해 달라는 요청이 있었고,
  이후 레이아웃·상호작용 변경은 전부 코드 검증(타입·린트·빌드·e2e)까지만 했다. 위 2번이
  그래서 남았다
- 로컬 도커가 한 번 죽어(Docker Desktop의 Inference manager 초기화 실패) 재시작해야 했다.
  컨테이너 동작 자체와는 무관한 부가 기능 오류였다

## 주의

- **`AUTH_SECRET`을 바꾸면 저장된 비밀번호를 전부 못 읽는다.** 세션만 끊기는 게 아니다.
  값이 이 키에서 파생되기 때문이다 (`src/lib/secret-crypto.ts`)
- **노트 본문은 마크다운 원문 그대로 저장한다.** 저장·조회 어느 쪽에도 변환을 넣으면
  MCP 왕복이 다시 손실된다. 표시할 때만 렌더한다
- **할 일 앵커는 인용문으로 위치를 잡는다.** 줄 번호로 바꾸면 앞에 줄이 추가될 때 조용히
  엉뚱한 곳을 가리킨다
- **`src/lib/note-render.ts`는 XSS 경계다.** 공개 공유 페이지가 익명 방문자에게 내보내는
  경로라, 태그나 속성을 늘릴 때는 이스케이프와 스킴 검사를 반드시 같이 본다
- 마이그레이션 `20260906180000_server_side_secrets`는 기존 `Secret` 행을 **지운다**.
  브라우저에서 암호화된 값이라 서버가 풀 수 없기 때문이며, 적용 전 나스에 비밀번호가
  없음을 확인하고 진행했다
