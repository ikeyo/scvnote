## 비밀번호: 브라우저 암호화를 걷어내고 서버 암호화로 (#7 → #8)

프로젝트 멤버끼리 비밀번호를 공유하려고 RSA-OAEP 봉투 암호화를 먼저 넣었다(#7). 계정마다
키쌍을 만들고 프로젝트 키를 멤버 공개키로 감싸 나눠주는 구조다.

이게 평문 HTTP에서 동작하지 않았다. `crypto.subtle`이 보안 컨텍스트에서만 제공되는데
나스를 LAN IP로 접속하면 조건을 못 맞춘다. node-forge 폴백을 넣어 우회했으나 이번엔 forge의
웹 워커 경로가 워커 스크립트를 못 찾아 무한 대기에 빠졌다 — `options.workers || 2` 때문에
`workers: 0`이 무시되는 함정이었다.

개발용 자격증명 보관에 이 복잡도가 맞지 않는다고 판단해 클라이언트 암호화를 통째로 걷어냈다(#8).

- `src/lib/secret-crypto.ts` 신규 — `AUTH_SECRET` 파생 키로 AES-256-GCM
- 삭제: `src/lib/crypto-client.ts`, `src/lib/vault-keyring.ts`, `src/components/VaultGate.tsx`,
  `src/app/api/vault/**`, `src/app/api/projects/[id]/shared-vault/**`
- `src/lib/access.ts` — 비밀번호 가시성이 노트·할 일과 같은 규칙으로 합쳐짐
- `src/app/api/secrets/[id]/value/route.ts` 신규 — 목록에는 값을 싣지 않고 한 건씩만 복호화
- 스키마: `User`의 vault 필드들과 `ProjectVaultKey` 삭제, `Secret.valueCipher`로 단순화
- node-forge 의존성 제거. 1,449줄 삭제 / 263줄 추가

## 노트 본문: TipTap JSON → 마크다운 원문 (#9)

MCP로 보낸 마크다운이 `# 제목` 글자 그대로 저장되던 문제. 변환 계층을 두는 대신 마크다운을
원문 그대로 저장하기로 했다 — 변환이 없어야 왕복이 무손실이다.

- 스키마: `Note.content`(Json) + `contentText` → `Note.body`(마크다운). 검색 인덱스도 본문에 직접
- `src/lib/markdown.ts` 신규 — 표시용 파서(직접 작성). 렌더러가 허용 목록 방식이라 어휘를 맞춰야 했다
- `src/lib/tiptap-render.ts` → `note-render.ts`. 링크 마크 렌더 추가(href 스킴 검사 포함)
- `src/components/Editor.tsx` — textarea + 미리보기로 교체
- `src/lib/mcp-tools.ts` — create/append/get이 본문을 그대로 주고받음
- TipTap 등 패키지 7개 제거. 1,048줄 삭제 / 218줄 추가

렌더링을 실제로 돌려 파서 버그 3개를 찾아 고쳤다: 역슬래시 이스케이프 무시,
`**굵은 데 *기울임* 도**` 중첩 강조 깨짐, `2 * 3 * 4`처럼 공백 뒤 별표가 기울임으로 먹던 것.
