# 태그

태그는 프로젝트/카테고리와 **직교하는 축**이다. 노트 하나는 프로젝트 하나 · 카테고리 하나에
속하지만 태그는 여러 개 붙을 수 있고, 프로젝트를 가로질러 묶인다.

관리 화면은 `/tags`. 노트 편집 화면에서는 제목 아래 칸에 쉼표로 구분해 입력한다.

## 이름 변경

**태그 이름을 바꾸면 그 태그가 붙은 노트 전부에 반영된다.** 노트를 하나씩 고칠 필요가 없다.

## 합치기 (merge)

이미 있는 이름으로 바꾸면 두 태그를 합치는 것이 된다. `docker` / `Docker` 처럼 표기가 갈린
경우를 정리할 때 쓴다.

합치기는 원래 태그를 지우는 파괴적 동작이라 **명시적으로 요청해야만 실행된다.**

- API에 `merge` 없이 요청하면 **409**로 거부한다
- 웹 UI는 409를 받으면 "노트 N건을 옮기고 기존 태그를 지울까요?"라고 먼저 묻고,
  승인한 경우에만 `merge: true`로 다시 보낸다

## 삭제

태그를 지우면 **노트에서 떨어지기만 하고 노트 자체는 남는다.** 확인 창이 몇 건에서
떨어지는지 미리 알려주고, 응답도 `detachedFrom`으로 알려준다.

## 미사용 태그 정리

노트를 지우면 그 노트에만 붙어 있던 태그가 고아로 남는다. 목록 상단의
**"미사용 N개 정리"** 버튼이 이것들을 한 번에 지운다.

기본 목록에는 사용 중인 태그만 나온다. 체크박스를 켜면 고아 태그도 보인다.

## API

| 요청 | 하는 일 |
|---|---|
| `GET /api/tags` | 사용 중인 태그 + 노트 개수. `?unused=1`이면 고아 태그도 포함 |
| `PATCH /api/tags/:id` | 이름 변경. 이름이 겹치면 409, `merge: true`면 합치기 |
| `DELETE /api/tags/:id` | 모든 노트에서 이 태그를 뗀다 |
| `DELETE /api/tags` | 고아 태그 일괄 삭제 |
| `GET /api/notes?tag=<이름>` | 태그로 노트 필터 |

## MCP

`list_tags`로 기존 표기를 먼저 확인하면 `docker` / `Docker` 같은 중복 생성을 막을 수 있다.
`search_notes`의 `tag` 인자로 범위를 좁힐 수도 있다.

태그의 이름 변경·합치기·삭제는 MCP로 노출하지 않는다. 여러 노트를 한 번에 바꾸는
파괴적 동작이라 웹 UI에서 사람이 확인하고 하는 편이 낫다.
