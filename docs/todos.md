# 할 일 (Todo)

프로젝트 단위로 **오류사항 · 개선사항 · 아이디어**를 모아두고 진행을 체크한다.
관리 화면은 `/todos`, 프로젝트별로는 사이드바 트리의 **할 일**.

## 종류

| 값 | 표시 | 쓰는 곳 |
|---|---|---|
| `BUG` | 오류 | 발견한 버그, 잘못 동작하는 것 |
| `IMPROVEMENT` | 개선 | 지금도 돌지만 더 나아질 수 있는 것 |
| `IDEA` | 아이디어 | 해볼 만한 것. 아직 할지 안 할지 모름 |
| `TASK` | 할 일 | 그 외 일반 작업 |

## 진행 상태

```
대기(TODO) → 진행 중(DOING) → 완료(DONE) → 대기
```

목록의 **상태 칩을 누르면 한 칸씩 넘어간다.** 별도 화면 이동이 없다.

- 완료로 넘길 때 `doneAt`이 찍히고, 다시 열면 지워진다
- 기본 목록은 **완료를 숨긴다.** "완료 숨기기" 체크를 풀면 완료 항목이 아래 묶여 취소선으로 나온다
- 사이드바 배지는 **완료를 뺀 남은 개수**다

## 프로젝트와의 관계

노트·비밀번호와 같은 규칙을 따른다.

- 미분류(`projectId = null`)가 기본값
- 프로젝트를 지워도 할 일은 남고 미분류로 이동한다 (`ON DELETE SET NULL`)
- 프로젝트 화면에서 추가하면 그 프로젝트로 들어간다

## 노트와의 연결

노트 편집 화면의 **할 일** 구역에서 그 노트에서 나온 항목을 바로 등록한다.
작업일지를 쓰다 오류를 발견했을 때 화면을 옮기지 않고 적어두는 흐름이다.
넓은 화면에서는 이 구역이 본문 오른쪽에 붙어서, 리뷰하면서 바로 적을 수 있다.

### 본문의 특정 대목에 달기

본문에서 **문장을 선택한 채로** 할 일을 추가하면, 그 문장을 인용문으로 함께 저장한다
(`Todo.anchorText`). 할 일 아래에 인용문이 표시되고, 누르면 본문의 그 자리로 이동해
선택 표시된다.

위치를 줄 번호가 아니라 **인용문으로** 잡는 이유는, 앞쪽에 줄이 추가돼도 가리키는 곳이
안 틀어지게 하기 위해서다. 대신 인용한 문장 자체를 고치면 못 찾는데, 그때는 조용히
엉뚱한 곳을 가리키는 대신 **"원문에서 사라짐"**으로 드러난다.

- **노트에서 만든 할 일은 그 노트의 프로젝트를 물려받는다.** 프로젝트를 따로 고를 필요가 없다
  (`projectId`를 명시하면 그쪽이 우선한다)
- 노트 구역에서도 상태 칩을 눌러 진행을 바꿀 수 있다
- **연결 해제**는 연결만 끊고 할 일 자체는 남긴다
- 할 일 목록에서는 📄 아이콘으로 원본 노트로 되돌아간다
- 연결된 노트가 지워져도 할 일은 남는다 (`ON DELETE SET NULL`)

## API

| 요청 | 하는 일 |
|---|---|
| `GET /api/todos` | 목록. `project` / `kind` / `status` / `q` / `note`로 필터 |
| `GET /api/todos?open=1` | 완료를 뺀 것만 |
| `POST /api/todos` | 추가 |
| `PATCH /api/todos/:id` | 상태·제목·종류·설명·프로젝트 변경 |
| `DELETE /api/todos/:id` | 삭제 |

`GET /api/projects`는 프로젝트마다 `openTodos`(남은 개수)를 함께 준다.
프로젝트 수만큼 쿼리하지 않고 `groupBy` 한 번으로 가져온다.

## MCP

| 도구 | 하는 일 |
|---|---|
| `list_todos` | 조회. 기본은 완료를 뺀 것만 |
| `create_todo` | 추가. `kind`로 구분, `noteId`로 노트에 연결 |
| `update_todo` | 상태·제목·종류·프로젝트·노트 연결 변경. **완료 처리에 쓴다** |

```
"ScvNote 프로젝트에 오류 하나 등록해줘 — 첨부 지워도 파일이 남는다"
"ScvNote에 남은 오류 뭐 있어?"
"그 trigram 건 완료 처리해줘"
```

삭제는 MCP로 노출하지 않는다. 태그와 같은 이유로, 되돌릴 수 없는 동작은 화면에서 한다.
